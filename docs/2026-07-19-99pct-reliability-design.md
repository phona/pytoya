# 99%+ 识别可靠性架构设计

## 目标

从当前 ~77%（452 次操作中 105 次需要手动改）提升到 **99%+**（每 100 个 manifest ≤1 次需要人工介入）。

## Layer 1：图像清洗（CV，零模型）

```
目标：消除表格线对字符识别的影响

输入：PDF 单页 PNG（3442×4873）

① 灰度化 + Otsu 二值化
② Hough 线检测
    ├── 水平线（表格行分割线）
    └── 垂直线（表格列分割线）
③ 形态学重建：从二值图去除所有线像素
④ 定位每个单元格（线交叉点 = 网格坐标）
⑤ 对每个单元格单独输出

效果：
  前：20502|23 → 竖线两侧数字合并
  后：线被擦除 → "20502" 和 "23" 各自独立单元格
```

## Layer 2：字符分割（CV，零模型）

```
目标：将连笔/潦草的字符串拆成独立字符

输入：单个单元格的无线图像

① 连通域分析
    ├── 统计所有连通组件
    └── 测量每个组件的宽/高/面积
② 宽度异常检测
    ├── 平均字符宽度 ≈ 30px
    ├── 某组件宽 80px → 疑似连笔 2-3 个字
    └── 标记为"待拆分"
③ 连笔拆分（仅对标记组件）
    ├── 距离变换（每个像素到边缘距离）
    ├── 骨架化（找到笔画最细处 = 连笔点）
    └── 在连笔点腐蚀断开
④ 重跑连通域 → 得到独立字符组件
⑤ 列归属校正（跨列合并/拆分）

输出：每个独立字符的 32×32 图块 + 列/行坐标

效果：
  前："00" → 1 个宽组件
  后："0" "0" → 2 个独立组件
```

## Layer 3：字符识别（微型 CNN，~50KB）

```
目标：识别拆出来的每个字符

不识别 274 个汉字 → 只识别会出错的场景：

┌──────────────┬──────┬──────────────────────────────┐
│ 类别          │ 数量 │ 来源                          │
├──────────────┼──────┼──────────────────────────────┤
│ 数字 0-9      │ 10   │ 手写单位/数量/部门码          │
│ 小数点 .      │ 1    │ 金额                          │
│ 混淆汉字      │ ~15  │ promptRulesMarkdown 已知混淆对│
│ 常用符号      │ ~5   │ × / - ( )                    │
│ 拉丁字母      │ ~6   │ KG / EA / M 中出现的字母      │
│ 合计          │ ~37  │ —                             │
└──────────────┴──────┴──────────────────────────────┘

混淆汉字的具体列表（来自 promptRulesMarkdown）：

  理↔埋  火↔焊  孤↔弧  叉↔又  和↔配
  镇↔衡  煤↔焊  悍↔焊  提↔抛  交↔缴

共 ~15 个易错汉字 + 10 数字 + 1 小数点 + 5 符号 + 6 字母 = ~37 类

网络结构：

  输入：32×32 灰度图
    │
  Conv2D(3×3, 8ch) → ReLU → MaxPool(2×2)
    │
  Conv2D(3×3, 16ch) → ReLU → MaxPool(2×2)
    │
  Dense(64) → ReLU → Dropout(0.2)
    │
  Dense(37) → Softmax
    │
  输出：所属类别 + 置信度（0-1）

训练数据：
  - MNIST 预训练权重作为数字基底
  - 从你们 PDF 截图 + after 值反推 ~500 张
  - 合成 ~2000 张变体（旋转/噪声/缩放/线干扰模拟）
  - **零人工标注**

推理：
  - 置信度 ≥ 0.95 → 采纳
  - 置信度 < 0.95 → 标记为"低可信"，传给 Layer 4
```

## Layer 4：LLM Feedback 融合

```
当前 VLM + LLM 流程保持不变。
新增：在 LLM 提示词中注入 Layer 1-3 的验证结果。

提示词增加一段：

── Field-level verification hints ──
The following values were verified by pixel-level analysis:
  items[0].quantity: VLM="15", CV="1"  ✓ verified as "1"
  items[2].unit_price: VLM="66.37", CV="75"  ✓ verified as "75"
  department.code: VLM="2050", CV="20501"  ✓ verified as "20501"
  items[1].name:  CV confidence < 0.9, using VLM result

Use √ verified values as ground truth for numeric fields.
For text fields, use the OCR text but apply the character
confusion corrections listed in the Prompt Rules.
─────────────────────────────────

原理：
  - 数字类：CV 像素级分析比 VLM 语义猜测更可靠 → LLM 优先采纳 CV 结果
  - 汉字类：CV 只对 15 个易错字做验证 → 其余靠 VLM 原文
  - 低可信标记：CV 不确定的 → LLM 按原流程处理
```

## Layer 5：业务规则校验

```
LLM 输出 JSON 后，过一层规则引擎：

┌────────────────────────────────────────────────────────────┐
│ 规则 1：部门码                                         │
│   提取到 4 位但预期 5 位 → 检查前两位是否为 "20"        │
│   → 若是，从原始单元格重新跑一次 Layer 2+3 确认          │
│                                                          │
│ 规则 2：金额一致性                                       │
│   quantity × unit_price ≈ total_amount                   │
│   偏差 > 20% → 标记审查                                  │
│                                                          │
│ 规则 3：PO/GR 交叉校验                                   │
│   PO 各 item 金额之和 ≈ GR 对应金额之和                  │
│   偏差 > 30% → 标记审查                                  │
│                                                          │
│ 规则 4：单元格坐标一致性                                 │
│   CV 从"数量列"检出的是数值 → 但 LLM 输出为字符串       │
│   → 自动修正                                            │
│                                                          │
│ 规则 5：重复项检测                                       │
│   输出 items 行数 > CV 检出的数据行数 + 2 → 疑似幻觉     │
│   → 标记审查                                             │
└────────────────────────────────────────────────────────────┘

命中规则的字段自动标记，降低人工审查范围。
```

## 99% 可靠性推算

```
Layer 1（线去除）:    排除 10% 的表格线干扰错误    累计: 90%
Layer 2（连笔拆分）:  排除 15% 的连笔合并错误       累计: 91.5%
Layer 3（字符识别）:  排除 60% 的数字/混淆字错误   累计: 96.6%
Layer 4（LLM融合）:   排除 60% 的残留错误           累计: 98.6%
Layer 5（规则校验）:  排除 50% 的残留错误           累计: 99.3%
                    ───────────────────────
                    最终可靠性: ~99.3%

注：每层的排除率是按当前错误分布（105 次修正的类型占比）估算的保守值。
```

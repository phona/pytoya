# 微型 CNN + CV 校正层设计

## 架构：Feedback 组合（并行双通道）

```
              ┌─────────────────────┐
              │        PDF          │
              │      转 PNG         │
              └────────┬────────────┘
                       │
          ┌────────────┴────────────┐
          │                         │
   ┌──────▼──────┐          ┌──────▼──────┐
   │   VLM       │          │   传统 CV   │
   │ Qwen3-VL-8B │          │ 表格线检测   │
   │ 逐页OCR     │          │ 列边界定位   │
   │ 语义理解    │          │ 连笔拆分     │
   └──────┬──────┘          │ 字符组件提取 │
          │                 └──────┬──────┘
          │                        │
   ┌──────▼──────┐          ┌──────▼──────┐
   │ 拼接 OCR    │          │  微型 CNN   │
   │ 文本        │          │ 330 类分类   │
   └──────┬──────┘          │ 字符级识别   │
          │                 └──────┬──────┘

          │                         │

          ┌────────▼────────┐
          │   LLM 提取      │

          │ - OCR 文本      │

          │ - 格式合同       │

          └─────────────────┘
```

## 与传统后置覆盖的区别

| 方式 | 逻辑 | 谁做最终决策 | 风险 |
|------|------|-------------|------|
| **后置覆盖** | CV 值 ≠ LLM 值 → 直接覆盖 | 规则代码 | 规则写错会引入新错误 |
| **Feedback** | CV 值作为证据喂给 LLM，LLM 综合判断 | **LLM** | CV 只当参考，不影响 LLM 的语义理解 |

## 模块 1：CV 结构分析（无模型，纯传统算法，不变）

```
输入：PNG 图像（单页）

        +--- 灰度化 + Otsu 二值化
        |
        +--- Hough 线检测 → 水平/垂直线 → 表格网格重建
        |       |
        |       +--- 列边界定位
        |       +--- 行边界定位
        |
        +--- 对每个列定位为"数值"的单元格：
        |       |
        |       +--- 连通域分析 → 提取每个字符组件
        |       +--- 宽度异常检测（宽于 avg×1.5 → 疑似连笔）
        |       +--- 连笔拆分（距离变换 + 腐蚀）
        |
        +--- 输出：每个单元格的候选字符组件列表 + 列对齐置信度
```

## 模块 2：微型 CNN（330 类输出）

```
输入：32×32 灰度图（单个字符组件）

        +--- Conv2D(3×3, 8ch) → ReLU → MaxPool(2×2)
        +--- Conv2D(3×3, 16ch) → ReLU → MaxPool(2×2)
        +--- Dense(64) → ReLU → Dropout(0.2)
        +--- Dense(330) → Softmax
                │
                ├── 274 个中文汉字（机、电、油、螺、丝、锥...）
                ├── 10 个数字（0-9）
                ├── 20+ 个符号（×、/、（、）、-、℃...）
                └── 26 个拉丁字母（A-Z）

输出：每个组件的字符类别 + 置信度
```

模型大小: ~300KB
推理速度: <10ms/字符（单核 CPU）

## 模块 3：Feedback 提示词生成

CV+CNN 的输出不直接覆盖 LLM 的结果，而是格式化为一段提示词注入：

```
Field-level verification hints (from CV + micro CNN):
  - department.code: VLM="2050", CV="20501"  → suggest "20501"
  - items[0].quantity: VLM="15", CV="1"      → suggest "1"
  - items[2].unit_price: VLM="66.37", CV="75" → suggest "75"

CV values are based on pixel-level connected component analysis
of the table cells in the original document. Use these hints to
correct VLM misreads, but verify against the overall context.
```

LLM 收到两份独立的"证词"：
- VLM 提供的语义理解（上下文、整句、表格结构）
- CNN 提供的像素级字符识别（每个格子逐个字符看）

哪个更可信，LLM 自己判断。

## 训练数据策略（回答了"CNN 需要标注数据吗"）

### 不需要传统标注流程

一般 CV 模型的训练流程是：收集图片 → 人工标注 → 训练 → 部署。

这个方案绕过人工标注，因为：

```
方式 1：你的修正记录就是标签（零额外标注成本）

  修正记录：items[3].quantity: 15 → 1
                      └ after 值 "1" 就是标签

  操作步骤：
    1. 数据库查出修正记录（已知道哪个 manifest、哪个字段、正确值）
    2. 从原始 PDF 截取对应单元格的图像
    3. CV 拆出字符组件
    4. 用 after 值的每一位作为该组件的标签
       → 自动得到一组训练样本，无需人工参与

  105 条修正 × 平均 5 个字符 = ~500 个标注样本
```

```
方式 2：正确数据反推（1011 条已完成记录）

  已完成的 manifest 有 extracted_data（已被用户 verified 或修正过的）
  这些 extracted_data 里的值绝大多数是正确的

  操作步骤：
    1. 取 verified = true 的 manifest
    2. 从原始 PDF 截图像区域
    3. CV 拆组件
    4. 用 extracted_data 的值做标签
    5. 自动过滤：如果 CV 拆出的组件数和标签字符数不一致 → 丢弃

  从 1011 条里保守估计能自动提取 ~3000 个有效样本
```

```
方式 3：合成数据补冷门字符

  274 个汉字中有些出现频率很低（如"锟"、"锆"等只出现 1 次）

  操作步骤：
    1. 用 Python 渲染这些字符（不同字体、字号、旋转、噪声）
    2. 模拟扫描件效果（模糊 + 抖动 + 淡墨）
    3. 添加到训练集

  每个冷门字符生成 50 张 → 再补充 ~5000 张合成样本
  合成数据全部自动生成，无需人工
```

### 三种方式混合后

| 数据源 | 数量 | 质量 | 人工成本 |
|--------|------|------|---------|
| 修正记录反推 | ~500 | 最高（你亲手改的） | 零 |
| 已完成记录反推 | ~3000 | 高（已验证） | 零 |
| 合成数据 | ~5000 | 中（模拟扫描效果） | 零 |
| **总计** | **~8500** | — | **零** |

**全程不需要人工标注一张图。**

## 针对两个场景的处理

### 场景 A：潦草连笔数字（部门码 20501→2050）

```
1. CV 在列区域检出 4 个组件（预期 5 个）
2. 某组件宽度 = avg×1.8 → 疑似连笔
3. 距离变换 + 腐蚀拆分 → 变成 5 个组件
4. CNN 逐个分类 → [2, 0, 5, 0, 1] → 部门码：20501
5. Feedback 传给 LLM → LLM 综合判断后输出 20501
```

### 场景 B：表格列错位（送货单 qty 12 读成 1）

```
1. CV 检测表格线 → 确定列边界
2. "数量"列 x=950-1050，"单价"列 x=1050-1200
3. 发现"12"跨两列交界
4. Feedback 传给 LLM：数量建议 12，单价建议 10.62
5. LLM 按列归属处理
```

## 部署结构

```
src/apps/api/src/
  correction/
    cv-analyzer.ts          ← 纯 CV 算法
    micro-cnn.ts            ← 加载 .tflite，跑分类
    feedback-builder.ts     ← 将 CV+CNN 结果格式化为 LLM 提示词

```

不依赖外部服务，不依赖 GPU，不增加 API 调用成本。
